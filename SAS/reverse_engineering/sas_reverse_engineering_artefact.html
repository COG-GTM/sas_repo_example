Executive summary

This repository is the AHRQ Medical Expenditure Panel Survey (MEPS-HC) example-code library. The SAS layer is a collection of 58 self-contained, batch/interactive analysis programs (no shared autocall library, no scheduler, no DB connections) that read public-use survey files from a local directory and produce survey-weighted estimates (expenditures, utilization, insurance coverage, conditions, regression). The dominant migration challenge is complex-survey statistics (PROC SURVEYMEANS / SURVEYREG / SURVEYLOGISTIC with STRATA/CLUSTER/WEIGHT + DOMAIN), not macro complexity.

A7 · Dependency & data-lineage map 🔴⚙️

Because every program is self-contained, there is no inter-program execution DAG — programs do not call or depend on one another. The only lineage is external file → program → printed estimates. The interesting lineage is within the linking programs, which join multiple MEPS files.

Conditions file (Hxxx) ──┐

Event/PMED file (Hxxxa) ──┘

A7.2 Hidden coupling 🔴

None found. No global macro variables, WORK datasets, or option state are shared between programs in a single session. This is the best-case scenario for migration: each program can be ported and validated in isolation.

A8 · Custom formats & lookup catalogs 🔴⚙️

Formats are defined inline with PROC FORMAT in 48 of 58 programs — there is no shared .sas7bcat catalog or FMTSEARCH dependency. They serve two purposes: (1) display labels in reports, and (2) recoding/binning continuous values. Both map cleanly to Python dicts / pd.cut.

🔴 Negative sentinel values. MEPS encodes inapplicable/refused/don't-know as negative numbers (-1, -7, -8, -9, -15). Formats and IF/THEN logic rely on these; in Python they must be handled explicitly (they are NOT NaN and must not enter sums/means).

B13 · SAS → Python behavioural gotchas

  • MERGE ≠ SQL join — no fan-out on duplicate BY keys; last-value-wins on same-named columns. Reproduce with explicit pandas merge + dedup.
  • Complex survey design (STRATA/CLUSTER/WEIGHT + DOMAIN) — must use Taylor-series linearization (Python statsmodels survey / samplics); naive means/SEs will be biased.
